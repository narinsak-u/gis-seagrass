# Physical Backend Layers

> **Superseded in part by [ADR-0002](0002-flat-clean-architecture-naming.md):** physical subfolder nesting and file-naming conventions are superseded by the flat four-layer layout (`domain`, `application`, `infrastructure`, `presentation`); all Clean Architecture dependency, ownership, transaction, and composition-root rules remain in effect.

The backend uses explicit physical layers, not only file-name conventions. Feature HTTP code owns controllers, guards, OpenAPI, and DTOs under `http/dto`; application code groups use cases and contracts; domain code owns pure business rules; infrastructure owns concrete Drizzle repositories. Persistence contracts use `*Repository` names, implementations use `Drizzle*Repository`, and non-persistence contracts keep role-specific names. Application and domain code remain framework- and database-independent, with dependency direction enforced by a lightweight architecture check. Cross-feature Site–Survey workflows live in one `site-survey-workflows` module with a single root `SiteSurveyModule`; it passes an opaque transaction context through application contracts and composes feature-owned repositories without duplicate module wrappers. External feature callers use public contracts and use cases, while the CLI composes the same adapters in its own infrastructure entrypoint. Existing API, database, spatial, and concurrency behavior remains unchanged.
