# Physical Backend Layers

The backend uses explicit physical layers, not only file-name conventions: each feature owns `http`, `application`, `domain`, and `infrastructure`; platform concerns and import orchestration have their own modules. Application and domain code remain framework- and database-independent, with dependency direction enforced by a lightweight architecture check. Site–Survey coordination stays in a dedicated application module and passes an opaque transaction context through ports, so the two feature modules share one Drizzle transaction without importing one another's infrastructure. This accepts extra module wiring to make ownership and dependency direction visible and testable; existing API, database, spatial, and concurrency behavior remains unchanged.
